# 자원 제약과 후속 검증 범위

이 전수평가는 동결된 P1의 리드 선택을 조사한다. 모델 구조·학습법의 최적성을
검증하는 실험이 아니며, 현재 모델의 성능을 하드웨어가 허용하는 최대 성능으로 보지 않는다.

## 기록으로 확인한 제약

| 항목 | 근거 | 해석 |
|---|---|---|
| RTX 3060 12 GB, batch 16 | records/01_design_decisions.md 단계 1 | 자원이 배치 선택에 영향을 준다고 명시 |
| RAM 16 GB, mmap·순차 로딩 | docs/REPRODUCIBILITY.md §1; records/04_run_history.md LTST v1–v3 | OOM과 처리 방식의 제약은 확인. mmap 자체가 분류 정확도를 낮춘다는 근거는 없음 |
| OOM 이후 resume 섭동 | records/03_eval_results.md §⑩ | mixed 실험에서 실제 발생. 이후 RNG 상태 저장과 clean 재학습으로 교정했다고 기록. 이를 모든 모델의 결함으로 일반화하지 않음 |
| N별 무작위 20조합 | scripts/ablation_nlead_curve.py; records/03_eval_results.md §⑥-b | 개별 최적 조합 미확인. 이번 전수평가가 직접 해소하는 공백. 자원 때문에 20회로 정했다는 명시 근거는 미확인 |

연구실 실측: RTX 5070 Ti 16 GB, RAM 약 31.1 GiB. 홈 PC 대비 VRAM은 12→16 GB로
증가했으며, 모든 대형 재학습이 자동으로 가능해지는 것은 아니다. 실제 학습 메모리·속도는
학습 실행으로 별도 측정해야 한다. 이번에 수행한 것은 추론 검증이다.

## 자원 제약과 구분해야 할 설계 선택

- frozen ECG-FM + rank-8 LoRA는 파라미터 효율 전이학습이라는 연구 목적도 갖는다.
  자원이 충분하면 full fine-tuning이 반드시 더 정확하다는 결론은 현재 근거로 낼 수 없다.
- 10초 입력은 사전학습·기존 인터페이스·데이터 처리 규격과 연결된다. GPU 제약만으로
  선택했다고 기록돼 있지 않다. 긴 기록의 정보 손실은 별도의 다중윈도우 검증 대상이다.
- mean pooling과 이소성 성능의 관계는 후보 가설이다. 과거 특정 실험에서 관측한
  AUROC ~0.82를 모든 데이터·모델의 표현 상한으로 일반화하지 않는다.
- 초기 설계 문서에는 mixed precision 필요라고 쓰였지만, 현재 train_lora_multitask.py에서
  autocast/GradScaler 사용은 확인되지 않았다. 실제 학습이 AMP였다고 단정하지 않는다.

## 후속 통제 실험 후보 (현재 미실행)

1. 평가 시 특징 마스킹 on/off의 의미와 배포 규격을 먼저 확정한다. 같은 모델에서도
   평가 난수가 지표를 바꾸므로, 학습 개선과 평가 변동을 혼동하지 않는다.
2. 원 train/val/test ID를 동결하고 여러 학습 seed로 현재 레시피 분산을 측정한다.
   재학습·하이퍼파라미터 선택은 train/val만 사용하고 test를 반복 선택에 쓰지 않는다.
3. LoRA rank, pooling/head, 부분 백본 해제를 한 번에 하나씩 비교한다.
   동일 초기 체크포인트·학습량·증강·유효 배치 크기를 맞춘다.
4. 메모리 증가를 우선 처리량 개선에 사용한다. 큰 물리 배치와 gradient accumulation을
   비교할 때 유효 배치·optimizer step 수를 맞춰 메모리 효과와 학습 레시피 효과를 구분한다.
5. 다중윈도우/구간 집계는 record 단위 split을 유지한다. 한 record의 창을 train/test로
   나누지 않고, 모든 모델에 동일한 평가 레코드·창 정책을 적용한다.

이 후보들은 별도 재학습 실험 계획이며, 현재 793개 리드 전수평가에 섞지 않는다.
